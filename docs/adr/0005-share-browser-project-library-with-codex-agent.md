# Codex Agent 与手动入口共享运行时项目库

Lumina 的产品形态是闭源、本机安装和本机运行的产品。一次性安装器只负责安装已编译的签名发布物；安装后的本地运行时是隐藏的后台服务，不展示桌面画布窗口。Chrome 是 Lumina 的画布界面，Codex 是第二个入口；两个入口必须始终连接同一份本机数据。普通用户不需要获取或运行 Lumina Git 源码。

一台电脑上的 Lumina 只有一个运行时项目库：用户手动打开的 Lumina URL、Codex Agent 入口和未来受控 widget 都通过本地运行时访问同一份项目、历史和资产。浏览器上下文只承载画布，不决定数据归属；Codex 内置浏览器和外部 Chrome 不会各自创建项目库。companion 只作为受控桥接边界，运行时项目库才是项目事实源。

## Consequences

- 未连接画布客户端时，Lumina 必须请求用户显式连接或打开画布，而不是把项目复制到隔离的替代存储。
- 本地运行时在首次安装后从非通用的 loopback 端口中选择一个可用地址，并将该 Origin 持久记录为该安装的入口；Agent 从本地运行时解析并打开同一地址。
- 首次选址遇到端口冲突时，本地运行时自动选择下一个可用地址。启动时端口若已被同一 Lumina 实例占用，应复用该实例；若被无关进程占用，必须进入显式修复流程，不能静默换一个 endpoint。
- 安装器注册 `lumina://open` 和 Lumina 书签作为手动入口；它们唤起本地运行时，再由本地运行时打开已登记的浏览器 URL，用户无需知道实际端口。
- 安装器必须在安装 payload 之外登记实际 runtime 可执行文件路径。Codex 插件按“显式开发覆盖、安装登记、旧版默认目录”的顺序解析该路径；登记存在但无效时进入 Repair，不得扫描磁盘或静默选择另一套安装。
- 普通用户安装只交付本机运行时发布物，不克隆或暴露 Lumina Git 源码；Git checkout 仅属于开发者路径。
- 更新、修复安装和重新安装必须保留已登记的 Origin 配置、运行时身份元数据和项目库；项目、历史、资产、偏好与凭据的连续性不依赖某个 Chrome Profile。卸载是否删除这些数据必须是独立、明确且默认保守的操作，不能由普通更新隐式触发。
- Windows 与 macOS 都是首发支持平台；两端的安装器和本地运行时必须遵守相同的入口、Origin 和运行时项目库语义。
- local-first 覆盖应用、项目数据、资产、bridge 和 GenerationGateway 的本机运行，不要求模型推理也在本机；GenerationGateway 仍可访问用户选定的远程模型供应商。
- 项目级写授权、独立生成授权、revision 校验和断线后的不重放规则保持不变。
- ADR-0004 的会话级 loopback Origin 仅可用于开发或显式隔离场景，不能作为普通 Codex 用户路径或项目库。

## Codex 插件浏览器表面修订（2026-08-23）

Codex Lumina 插件可以在 Codex 内置浏览器中打开已登记的 Lumina URL，也可以使用经授权的画布客户端。不同浏览器存储上下文不再决定项目、历史或资产连续性：它们都是运行时项目库的客户端。插件说明和验收仍必须验证实际入口、授权和 revision，但不得把同一 Chrome Profile 或 IndexedDB 共享当作数据连续性的前提。
