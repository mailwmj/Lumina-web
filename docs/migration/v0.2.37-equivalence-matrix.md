## Web 运行时

`src/runtime/runtime.ts` 只报告 Web 模式和应用版本。项目、资产、设置、生成和媒体通过浏览器
仓库与 GenerationGateway 组合；下载和经用户授权的 File System Access 提供输出能力。

## 证据规则

1. 自动测试必须能在移除实现后失败，不能只检查模块是否可导入。
2. 手测证据记录浏览器、视口、语言/主题和主路径截图或录屏位置。
3. 异常路径证据记录输入、可见错误、状态恢复结果和是否产生副作用。
4. 发布前，任何仍标记“待补”的行都阻塞“功能等价”结论；本矩阵作为迁移进度基线，具体闭环由对应迁移票实现。

## Machine-checkable release gate

`v0.2.37-release-contract.json` freezes the nine required rows and the release
test plan. `v0.2.37-release-evidence.json` is its machine-readable evidence
counterpart. `npm run verify:web-release -- --channel auto` runs the Web-only,
type, Vitest, Gateway, companion, plugin, dependency-audit, scoped-lint,
production-build, artifact, and Chromium E2E checks, then derives the release
tier from the recorded evidence. The contract requires separate records for
the latest and previous Chrome and Edge majors plus Codex Chromium; each must
cover project, assets, generation, import-export, and offline behavior.
Verified manual records must identify the browser, version, viewport, locale,
theme, and capture artifacts; verified exception records must identify the
test files, input, visible result, recovery, and side effects. A `complete`
channel is accepted only when every frozen required row has verified evidence
and product confirmation. The checked-in report deliberately remains Beta
until that evidence exists; tag releases use that same decision to publish
Beta evidence as GitHub prereleases.

Each supported-browser record also fixes its stable or Codex channel,
latest/previous/representative role, dotted browser version, and a capture
timestamp no more than 35 days old. Chrome and Edge latest/previous records
must use adjacent majors. A verified row-level manual record must link its
`browserEvidenceId` and match that recorded browser and version, so it cannot
substitute an unrelated browser capture for the required support evidence.
