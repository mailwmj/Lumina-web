# 在 Codex 中使用 Lumina 完成电商工作的典型流程

这里的“电商工作”特指商品内容生产与交付，不包含订单、库存、定价或店铺后台发布接口。这条流程适合为一个 SKU 产出商品主图、模特图、细节图、生活方式图，以及可选的分镜和短视频。Codex 负责理解需求、读取当前画布和提交边界明确的画布操作；Lumina 页面负责素材确认、运行授权、结果查看和文件下载。

## 先确认前提

### 目标

把“商品事实不能漂移、镜头可以迭代、每个结果可追溯”作为验收标准，而不是只追求一张看起来漂亮的图。

### 前置条件

- 已安装并能启动 Lumina Runtime，Lumina Canvas 插件已在 Codex 中启用。
- Codex 可以使用内置浏览器。Lumina 的 Codex 正式入口是 Codex 内置浏览器，不是 connected Chrome。
- Codex 启动环境的 Node.js 满足插件要求（当前为 `>=18`）。Lumina 普通使用不需要用户运行源码、Git、npm 或终端。
- Lumina 中已经配置可用的图片或视频供应商；不要在 Codex 对话中粘贴 API Key。
- 用户准备好商品参考图、模特或场景参考图，以及本次要交付的渠道和画幅要求。

### 关键边界

| 事项 | 当前行为 |
| --- | --- |
| 项目、历史和资产 | 由已安装 Runtime 的项目库持久化；浏览器 IndexedDB 只保存独立设置。 |
| Codex 写入 | 只提交受限的创建、更新、移动和连线变更，并作为一个可撤销的变更集执行。 |
| 图片导入 | 用户先在 Lumina 页面上传；Codex 只能使用用户提供的 HTTPS 图片或栅格 base64，不请求本机路径或 `file://`。 |
| 图片/视频生成 | 每次运行都需要当前 Lumina 页面中的单独确认；Codex 不应静默提交计费请求。 |
| 结果交付 | Codex 可读取受限元数据和压缩预览；原始图片/视频下载在 Lumina 页面完成。 |

## 主流程

```mermaid
flowchart LR
  A[明确 SKU 与交付物] --> B[打开 Lumina]
  B --> C[选择或创建项目]
  C --> D[上传并命名参考素材]
  D --> E[搭建提示词与节点关系]
  E --> F[检查参数与待运行节点]
  F --> G[用户单独授权运行]
  G --> H[生成并等待结果]
  H --> I[按单变量迭代与质检]
  I --> J[分镜或视频扩展]
  J --> K[平台检查与下载交付]
```

### 1. 在 Codex 中先定义本次电商任务

先说清楚商品、输出数量和硬性保留项。不要一开始就让 Codex“直接生图”。例如：

```text
我要为 SKU-A102 产出一组电商素材：
- 1 张 4:5 模特主图，完整展示上衣版型；
- 1 张 45 度袖口动作图；
- 1 张木质住宅环境中的生活方式图；
- 1 张领口、肩线和针织纹理细节图；
- 通过后再做 5 秒单图短视频。

商品颜色、领型、肩线、袖长、袖口、下摆、针法、纱线粗细和整体松量必须以商品参考图为准。
模特脸部、肤色、发型和身体比例必须以模特参考图为准。
先给我画布方案和提示词，不要创建节点，也不要运行生成。
```

Codex 应先返回镜头清单、需要的参考图职责和待确认事项。若商品结构或模特身份无法从已明确的参考图中判断，应先提问，而不是自行补全。

### 2. 打开并连接 Lumina

在同一个 Codex 任务中输入：

```text
打开 Lumina，并连接当前画布。连接后只汇报项目名称、节点数量、选中节点和当前是否可写；不要修改或运行任何节点。
```

正常顺序是：Codex 调用 `canvas_open`，在 Codex 内置浏览器打开返回地址，等待 Lumina 页面完成 bridge handshake，然后读取画布状态。

如果返回 `awaiting_project`，说明连接成功但还没有活动项目；不要把它当成插件失败。若 Codex 内置浏览器不可用，应停止并提示用户启用它，不能切换到 connected Chrome 或创建另一个项目库。

### 3. 选择或创建项目

在 Lumina 内置浏览器中选择已有项目，或批准创建一个新项目，例如 `SKU-A102-2026-08-28`。项目切换和创建都需要用户在 Lumina 页面明确确认。

确认后让 Codex 重新读取完整状态：

```text
读取刚才选中的项目。只报告项目 ID 的非敏感摘要、节点类型及数量、当前 revision 和可用能力；不要复用其他项目的上下文。
```

Codex 只能在该项目仍然活动、revision 仍然有效时继续操作。项目切换、断线或 token 轮换后，旧的写入授权和运行授权都不再适用。

### 4. 在 Lumina 页面准备并命名素材

用户在 Lumina 页面上传并整理素材，建议至少准备：

- 商品正面、背面或细节参考图；
- 模特身份参考图；
- 必要时的场景或光线参考图；
- 若要做首尾帧视频，再准备明确的首帧和尾帧图片。

给节点使用可读名称，例如“商品参考-正面”“商品参考-背面”“模特身份参考”。然后告诉 Codex：

```text
素材已上传。读取当前选中素材的缩略预览和可见元数据，确认每张图的职责；不要读取本机路径、凭据或未选中的私有文件。
```

多图任务中要固定图片职责：图片 1 是模特身份，图片 2 是商品事实，图片 3 才是可选的场景或已通过的基准图。不要让场景图中的人物或服装被误当成商品事实。

### 5. 让 Codex 搭建第一版画布

建议先做最小可验收闭环：参考图 + 一个镜头提示词 + 一个 AI 生图节点。可以让 Codex 创建文本节点、图片生成节点并建立明确连线，但不要让它手动创建结果节点：

```text
基于当前项目创建第一版“SKU-A102 主图”工作流：
1. 建立一个可编辑的提示词节点，写入正面全身 4:5 主图要求；
2. 建立一个 AI 生图节点，使用当前图片参考和该提示词；
3. 设为 4:5、2K、单张输出；
4. 只创建必要节点和连线，不运行生成，不创建结果节点；
5. 完成后列出将要运行的节点、模型、画幅和提示词摘要。
```

这次操作应作为一个可撤销的变更集提交。若项目处于只读状态，Codex 应说明需要在 Lumina 页面获得当前项目的受限写入权限，而不是绕过权限写入。

### 6. 先审提示词和参数，再批准运行

检查重点：

- 商品颜色、版型、领口、袖口、下摆和针织纹理是否写成不可变事实；
- 模特身份和体型是否锁定；
- 本张是否只有一个主要动作、一个视线方向和清楚的承重关系；
- 光线、背景和道具是否服务于商品，而不是遮挡商品；
- 画幅、尺寸、输出数量和模型是否符合渠道要求。

需要调整时，用单变量指令，例如：

```text
只修正商品约束：恢复商品参考图中的领型、袖口罗纹宽度、下摆长度和针法分布。
模特身份、姿态、机位、窗光、背景、白平衡和画幅全部保持不变。
不要运行。
```

提示词和参数确认后，再明确要求运行授权：

```text
配置已确认。现在只总结待运行节点、模型、尺寸、输出数量和本次可能产生的计费动作，向我请求一次运行确认；在我确认前不要运行。
```

### 7. 授权并生成第一张基准图

用户在 Lumina 页面批准本次运行后，再发送：

```text
我已在 Lumina 页面确认运行。请只运行刚才确认的图片节点，等待终态，并返回每个结果的状态、压缩预览和可追溯的来源节点；不要提交新的任务。
```

Codex 使用已有图片节点运行并等待 `queued`、`running`、`succeeded`、`failed` 或 `cancelled` 等实际状态。成功时会出现新的结果图片节点，原始参考节点保持不变；失败时保留失败状态，不能通过“再点一次”隐式重试。

第一张主图通过身份、商品结构、颜色、手部和基本构图检查后，再把它作为系列基准。后续每张图都重复不可变事实，只替换镜头段，减少系列漂移。

### 8. 通过分支和单变量迭代补齐电商图组

从已通过的结果图片分支，而不是覆盖原节点。典型顺序是：

1. 复制商品和身份约束，生成 45 度袖口动作图；
2. 生成木质住宅中的生活方式图，保持商品颜色中性准确；
3. 生成领口、肩线、袖口和纱线纹理细节图；
4. 对需要的结果使用裁剪、标注或再次生图，所有加工都产生新的结果节点。

每轮只修一个最高优先级问题。硬门槛包括：身份不漂移、商品结构不重设计、颜色可比、手指和承重关系合理。失败的候选可以保留用于对比，但不能作为后续系列的事实源。

### 9. 需要时扩展为分镜和短视频

当静态图组通过验收后，再进入动态内容：

- **分镜：** 创建分镜生成节点，设置行列和每格描述；得到一张完整分镜图后，可用“切割分镜”生成可逐格编辑的分镜节点。
- **单图视频：** 将一张已通过的结果图片连接到视频生成（单图）节点，提示词只描述动作、镜头和节奏。
- **首尾帧视频：** 必须把两张图片分别连接到“首帧”和“尾帧”位置，不能只依赖连接先后顺序。

视频运行仍然需要一次新的、当前的 Lumina 页面确认：

```text
请检查视频输入是否满足单图或首尾帧要求，汇报模型、分辨率、时长和输入图片，然后向我请求本次视频运行确认。不要自动运行。
```

确认后，Codex 等待视频结果并读取安全的元数据、海报或末帧预览。视频字节、供应商 URL、任务句柄和本机路径不会返回到 Codex。

### 10. 平台检查和交付

在 Lumina 页面完成最终人工检查和下载：

- 主图是否完整展示商品，头脚或关键商品边缘没有被不合理裁切；
- 颜色、图案、材质和变体是否与实际 SKU 一致；
- 是否覆盖正面、角度、细节和生活方式场景；
- 目标渠道的比例、尺寸、文件格式和背景要求是否满足；
- 若平台要求，保留图片的 AI 生成/合成来源元数据；
- 下载前确认导出的文件来自已通过验收的结果节点，而不是草稿或失败节点。

可以让 Codex 做最后一次只读核对：

```text
只读检查 SKU-A102 的最终节点：按主图、角度图、细节图、生活方式图和视频列出结果状态、来源关系、画幅和待人工确认项。不要修改、运行或删除任何内容。
```

## 断线、失败和恢复

| 现象 | 正确处理 |
| --- | --- |
| `awaiting_browser` | 在 Codex 内置浏览器打开 `canvas_open` 返回的地址并等待握手；不要换到其他浏览器。 |
| `awaiting_project` | 在 Lumina 页面选择或创建项目并确认，然后重新读取完整状态。 |
| 项目只读 | 检查是否有另一个编辑器持有 Runtime lease；在 Lumina 页面完成允许的交接或保持只读。 |
| `stale revision`、断线、超时或 token 轮换 | 不要重放旧写入、导入或运行请求；重新 `canvas_open`、握手、读取当前项目，再提出新操作。 |
| 图片或视频生成失败 | 保留失败节点和错误状态，检查供应商/模型/输入约束；修复后由用户明确发起一次新的运行。 |
| 页面刷新后任务仍在供应商侧 | 只查询原任务绑定，不重新提交同一笔生成；达到恢复阈值后要求用户显式重新查询。 |
| Codex 没有 Lumina 工具 | 检查插件是否启用、Node.js 是否为 `>=18`，修复后新建 Codex 任务再试。 |
| Runtime 缺失、版本不兼容或元数据无效 | 使用 Lumina Repair 或更新插件；不要手动复制项目库，也不要创建第二个库。 |

## 完成标准

一次电商工作可以称为“在 Codex 中使用 Lumina 完成”，至少应满足：

- Codex 在内置浏览器中连接到正确的 Lumina 项目；
- 所有写入和计费生成都有边界和当前授权；
- 原始素材、提示词、结果和加工分支仍可追溯；
- 至少一张主图、一个角度或生活方式镜头和一张细节图通过人工商品真实性检查；
- 视频（如有）已通过输入关系、状态和成片预览检查；
- 最终文件在 Lumina 页面下载，并完成目标平台的规格与披露要求核对；
- 发生过断线或 revision 过期时，没有重放旧请求或产生重复计费任务。
