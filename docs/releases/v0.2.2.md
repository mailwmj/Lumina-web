## 新增

- 前端结构化日志系统：命名空间（按文件路径自动生成）、级别（debug/info/warn/error）、结构化字段、运行时配置
- Dev-only 浮动日志面板（Ctrl+Shift+L 切换显示，避开输入控件）
- 设置 → 日志分类：全局级别、模块级别覆盖、控制台输出、持久化、控制台时间戳、打开日志目录、复制最近 100 条、清空、重置
- 后端 Tauri command `append_frontend_log`，前端日志通过后端 `tracing` 同源持久化到 `storyboard.log`
- 后端 Tauri command `open_log_dir`，一键打开日志目录
- 启动时自动清理 14 天前的旧日志文件
- 单元测试基础设施：vitest 集成，36 个测试覆盖 levels/namespace/serialize/ringBuffer/config/transport
- ESLint 集成：`no-console: warn` 规则强制收敛直接 console 调用

## 优化

- 统一前后端日志时间线：前端日志通过 Tauri IPC 送到后端，复用现有 `tracing` 文件 appender 写入同一 `storyboard.log`，target 标记为 `frontend`
- SessionId 关联：每次启动生成唯一 session_id，写入启动日志并附加到每条前端日志
- 字段序列化保护：循环引用标记为 `<circular>`，大对象（>10KB JSON）截断并标记 `__truncated`，Error 实例展开为 `{ __error, name, message, stack }`
- IPC 批量节流（200ms flush），避免高频日志淹没 Tauri 通道
- Tauri 不可用降级：仅 `npm run dev` 时跳过 IPC，console + ring buffer 仍正常工作
- 前端 ring buffer（500 条循环覆盖）服务于内置 UI 面板

## 修复

- 替换散乱的 160 处 `console.*` 调用为统一 `logger.*` 调用，统一命名空间和级别
- 移除旧的 `log_frontend_debug` 和 `write_debug_log` 临时方案（前后端一并删除），改用新的 `append_frontend_log` 走 tracing 体系
- 移除旧的独立 `frontend_debug.log` 文件（合并到 `storyboard.log`）
- 修复 logger API 兼容性问题：支持 `console.log(msg, var1, var2, ...)` 风格的变长参数（自动包装为 `{ args }` 或保留单对象为 fields）
